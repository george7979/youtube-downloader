# Add Subtitles (.srt only) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** When the video is already in the folder and the chosen language's `Title.<lang>.srt` is missing, offer "Add subtitles (<lang>)" (window) / add it automatically with `--srt` (CLI), fetching only the subtitles.

**Architecture:** Same shape as "Add transcript": `Service.download` computes `addable_srt` on the `already_exists` result and, when the request carries `add_srt=True`, runs the existing subtitles-only engine path (`note_only=True`, no note target) and writes only the `.srt`. The window shows a second variant of the filled dialog button; the CLI sets `add_srt` from `--srt`.

**Tech Stack:** Python 3.12, CustomTkinter, pytest.

**Spec:** `docs/superpowers/specs/2026-10-19-srt-only-design.md` (accepted by the PO), extending `docs/superpowers/specs/2026-10-19-transcript-languages-design.md`.

## Global Constraints

- `ytdownloader/core/` never imports `tkinter`/`customtkinter`; GUI and CLI call only `Service` and `ToolManager`.
- UI and CLI text in English; tests never use the network (`FakeRunner`/`NoRunner`).
- Existing `.srt` files and notes are never overwritten, modified or deleted — this also holds for the existing "Add transcript" path, which today rewrites `Title.<lang>.srt` if it exists.
- At most one filled button in the "Already downloaded" dialog: "Add transcript (<lang>)" wins; "Add subtitles (<lang>)" only when no transcript can be added.
- Recent unchanged by adding subtitles; "Download again" (`force`) unchanged; the `Title [ID]`-without-note + `.srt` case unchanged.
- README "How it works", PRD, TECH and the skill describe a changed rule in the same commit.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; branch `dev`, no push.

## Review Focus

1. `Title.<lang>.srt` already there → no button, never rewritten (Task 1 test, including the Add transcript path).
2. Notes turned off (`save_note=False`) with video + main note present → "Add subtitles" still offered (Task 1 test).
3. Empty VTT → no `.srt` file (Task 1 test).
4. Both rules apply (other language, `.srt` ticked) → only `addable_lang`, and adding writes note + `.srt` (Task 1 test).
5. Cancel while adding subtitles → no partial `.srt`, video and notes untouched (Task 1 test).

### Task 1: Service — offer and write a missing `.srt`

**Files:**
- Modify: `ytdownloader/core/models.py`, `ytdownloader/core/service.py`
- Modify: `README.md` ("How it works": "The note"/"File names and downloading again"), `docs/PRD.md` (req. 6), `docs/TECH.md` (`service.py` row, "Notatki językowe" or a sibling paragraph)
- Test: `tests/test_service.py`

**Interfaces:**
- Produces: `DownloadRequest.add_srt: bool = False`; `DownloadResult.addable_srt: str | None = None` (language code, set only on `already_exists=True` results).
- Rule: in the existing `already_exists` branch (`service.py`, where `addable_lang` is computed), `addable_srt = track.lang` when `req.save_srt` and `track is not None` and `addable_lang is None` and `not (folder / f"{names.base}.{track.lang}.srt").exists()`. With `req.add_srt` and `addable_srt` set → engine run `note_only=True`, `media_only=False`, no note target; write only `Title.<lang>.srt`; result `already_exists=False`, `media_path` = existing media, `note_path` = existing main note (or `None` if absent), `srt_path` = new file, `transcript="none"`; status line `f"Video already here — adding {track.lang} subtitles."`.
- No VTT, or a VTT with no cues → no `.srt`, `srt_path=None`, warning `"No subtitles were downloaded."` once.
- In both add paths (transcript and srt) an existing `Title.<lang>.srt` is never rewritten.
